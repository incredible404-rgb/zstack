# 模型中立提示原则

这些原则描述提示设计的底层机制。它们是可迁移的工程假设，仍需在目标模型和真实工作负载上验证。

## 1. 提示是行为合同

一份有效提示应降低模型对以下问题的猜测量：

- 最终要交付什么；
- 哪些事实和材料可作为依据；
- 什么条件代表已经完成；
- 哪些动作已获授权；
- 输出必须保留哪些信息；
- 何时继续、追问、回退或停止。

合同越清楚，越少需要靠角色扮演口号、夸张强调或隐藏的共同理解补洞。

## 2. 结果优先，过程按必要程度规定

强模型通常能从清楚的目标、约束和完成标准中选择有效路径。过度规定每一个思考步骤会增加长度、制造冲突，也可能阻止模型适应新输入。

过程说明在以下情况仍然必要：

- 步骤顺序影响安全或正确性；
- 某项检索、审批或验证不能跳过；
- 需要可复现的合规流程；
- 目标模型在真实测试中反复漏掉关键步骤。

因此，默认写目的地；在有证据的缺口处加最小脚手架。

## 3. 精简是一种冲突控制

上下文中的每条规则都会与其他规则争夺注意，也可能产生语义重叠。精简的价值主要来自：

- 降低重复规则之间的细微差异；
- 减少无关工具和示例干扰路由；
- 让真正不变量更容易辨认；
- 降低长会话中重复前缀的累积成本。

精简不等于追求最少字符。删掉成功标准、权限、证据或验证，会得到短而脆的提示。

“一条规则只说一次”也是条件策略。OpenAI 的 GPT-4.1 长上下文指南曾建议把关键指令放在长材料的开头和结尾，而 GPT-5.6 指南倾向去重。这说明指令位置、模型代际和上下文长度会改变最优做法。默认保留单一权威表述；只有真实测试显示关键不变量在目标模型或长上下文中丢失时，才有意重复一条短提醒，并保持措辞一致、记录原因。

重复内容的功能也不同。反复写“先问我、不要改”这类宽泛限制，可能诱发多余审批；针对弱遵循模型的完成条件、持久性提醒或关键不变量，则可能提高 Agent 稳定性。不要把两者合并成“重复一律有害”或“关键规则一律首尾重复”，分别用代表性任务验证。

稳妥做法是从能工作的版本开始，一次移除一组内容，用同一批任务复测。OpenAI 给出的 10–15% 分数提升及 token、成本降幅来自其 GPT-5.6 内部 coding-agent 样本，只能当方向性证据，不能推广成所有模型的固定收益。

## 4. 决策规则比宽泛绝对词更稳

“永远搜索”“任何时候都先提问”“只用一个工具”把情境判断压成硬开关。边界一变，规则就互相打架。

对判断题写：

```text
当 [会改变结果的条件] 成立时，执行 [动作]；
当 [足够条件] 成立时，执行 [替代动作]；
在 [停止条件] 时结束或升级。
```

把 ALWAYS、NEVER、must、only 留给安全不变量、必需字段和真正禁止的副作用。

## 5. 自治应和影响半径匹配

频繁询问会让低风险工作停滞，放任一切又会扩大副作用。更稳的边界按影响半径划分：

- 读取、检查、分析和报告通常可直接进行；
- 用户明确要求修改时，本地、可逆、范围内的改动和非破坏验证通常可直接进行；
- 外部写入、不可逆操作、购买、隐私披露、权限提升和明显扩展范围需要确认。

运行时安全政策和用户当前指令可以进一步收紧边界，提示不得自行放宽。

## 6. 工具路由取决于信息流

工具多不等于能力强。工具选择应回答：

- 该工具是否提供完成任务所需的独特信息或动作；
- 调用之间是否独立；
- 中间结果是否需要新的语义判断；
- 是否存在副作用或审批；
- 最终回答是否必须保留原生引用或附件；
- 错误、空结果和部分结果怎样处理。

并行适合互不依赖的读取。批量程序适合边界明确的筛选、连接、去重、聚合和确定性验证。需要逐步判断、审批或引用保真的工作宜直接调用。

## 7. 证据预算围绕承重主张

检索过少会猜，检索过多会稀释重点。提示应定义：

- 哪些主张必须有来源；
- 什么类型的来源足以支撑该主张；
- 何时因证据缺口继续检索；
- 何时缩小结论、标记推断或承认未知。

“没有找到”只描述本轮检索结果，不自动证明对象不存在。追加检索应服务于关键事实、冲突或用户要求的覆盖面，不服务于润色。

## 8. 长度是内容优先级问题

“简洁”在不同模型、任务和产品里含义不稳定。更可靠的规则会列出：

1. 必须保留：结论、依据、限制、决定、下一步；
2. 可以压缩：次要背景、示例和解释；
3. 优先删除：开场、重复、通用安慰、无信息量总结和签名。

这样即使原生 verbosity 不可用，模型仍知道如何裁剪。

## 9. 人格与协作行为应分开

人格决定语气、温度、直接程度、幽默和语言指纹。协作行为决定何时追问、如何处理分歧、是否主动推进、怎样承认未知和检查工作。

两者都不应承担：

- 当前任务目标；
- 工具能力；
- 权限实现；
- 安全政策；
- 事实来源；
- 输出成功标准。

将这些职责混入人格，会让角色声线承担本应由运行时保障的可靠性。

## 10. 适配先于模仿字段

跨模型迁移时，先识别意图，再寻找目标运行时的等价能力。例如：

- “投入更多计算”是意图，某供应商的推理档位参数只是其中一种实现；
- “控制细节量”是意图，原生 verbosity 或文本内容优先级都是实现；
- “稳定输出字段”是意图，JSON Schema、函数参数或文本模板是不同实现。

若目标能力未知，保留意图和降级方案，不猜字段。

## 11. 验证闭合行为回路

模型输出具有变异，提示也会随模型版本、工具集和上下文变化。可靠流程是：

1. 用真实输入建立基线；
2. 定位一个具体失败模式；
3. 做最小、有因果假设的改动；
4. 重跑同一批案例；
5. 检查质量、完整性、证据、副作用、延迟和成本；
6. 保留可回滚版本。

提高推理预算之前，先检查目标、依赖、工具路由、验证和完成标准是否缺失。
