# 独立复核标尺（REVIEW.md）

独立复核（各客户端的 `reviewer` 子代理、PR 审查或跨模型交叉复核）开工前先读本页。它补充角色自带提示，冲突时以本页为准。

## 输入

简报应给出：**目标**（或 plan：改哪些文件、顺序、风险、怎么证明）、**改动范围**（diff 或文件清单）、**作者跑过的验证命令及真实输出**。缺目标就按改动本身推断并在结论里注明「未给目标」；缺验证输出直接记一条 P1「未验证」。

## 三遍审查

每条发现标明它属于哪一遍：

- **正确性**：逻辑错误、边界条件、回归风险、并发竞争与跨平台编码（如 Windows 路径、CRLF、字符集）。另查四类高频漏项：
  1. 修复是否违背已有契约（相关旧 issue 或既有测试守卫的行为）；
  2. 同一件事的所有入口是否都已覆盖（只修了一个调用点的，列出漏掉的入口）；
  3. 是否在用一个补丁掩盖另一个底层 bug；
  4. 新加的断言在实现真的出错时会不会如期失败（防止假绿测试）。
- **安全与数据**：凭据/私钥/个人身份信息混入 diff 或日志、越权访问、不可逆的删除或覆盖、对外副作用缺少确认。
- **对齐**：改动是否真正达成了目标或 plan；是否存在超出范围的顺手重构、漏做的步骤，或与项目 `AGENTS.md` 硬边界冲突之处。

## 分级

- **P0（阻断）**：会造成错误结果、丢数据、泄露凭据、违反硬边界，或削弱验证本身。修 bug 时为了变绿而删测试、跳过测试、放宽断言、改期望值，一律判 P0（除非简报明确证明原测试本身写错并附依据）。
- **P1（交付前修）**：可复现的缺陷但影响面受限；有测试设施的仓库修 bug 却未提供先红后绿的回归测试；缺验证输出。
- **P2（只记录）**：可读性、命名、局部风格等次要改进。单次复核最多列 5 条 P2，超出部分只报条数，避免噪音淹没重点。

## 不报

钩子、linter、格式化工具、CI 已经确定性拦截的问题；自动生成产物；无客观依据的纯个人偏好。每条发现必须附证据（`文件:行号`、复现命令或与目标的具体矛盾点），拿不出证据的不报。
