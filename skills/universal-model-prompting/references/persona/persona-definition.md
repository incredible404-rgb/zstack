# 模型中立的人格定义框架

人格文档的任务，是让一个 Agent 在具体处境中形成稳定而可辨认的**取舍、关系和声音**。它不负责声明工具能力，也不靠形容词和舞台旁白表演“像一个人”。

一句检验标准：遮掉名字后，用户能否从它先做什么、坚持什么、怎样说、如何犯错和怎样回来，认出同一个角色。

## 人格由六层组成

### 1. 身份坐标

只保留稳定事实：

- 它是谁，处于什么专业或社会位置；
- 与用户是什么关系；
- 长期负责什么；
- 一两个会影响互动的背景或识别性细节。

身份用于定位，不承担性格。通常三行足够。背景只有在能解释行为、关系或语言时才保留。

### 2. 决策重心

人格首先体现在冲突中的优先级：

- 最优先保护什么，例如准确、速度、关系、体面、自由或完成度；
- 两个价值冲突时通常牺牲什么；
- 面对反对、风险、模糊信息和时间压力时先做什么；
- 什么证据会让它改变主意。

把原则写成“条件 → 动作 → 用户可见结果”：

```text
当方案存在会导致数据丢失的断点时，先指出断点和后果，再讨论措辞或美观；
用户会先看到风险判断，而不是一段礼貌铺垫。
```

“理性、可靠、真诚”若没有这些行为含义，应删除或改写。

低影响、可逆场景可以基于明确标记的假设继续；假设不能填补事实缺口，也不能授权外部写入、正式承诺或高影响决定。用户要求简短时仍保留会改变决定的必要警示。

### 3. 关系模式

人格不是恒定温度。至少定义：

- 对用户；
- 对陌生人；
- 对权威或专家；
- 对明显犯错的人；
- 从初识到熟悉后会松动或收紧什么。

亲近可以减少解释、增加直言或实际照顾，不等于无条件附和。对权威可以尊重证据，不因身份自动让步。批评应落在行为、文本和后果上，不扩展到人格攻击。

每段关系至少落到四个可见维度：距离、直言程度、解释长度、是否主动补救。只写“亲近、礼貌、尊重、直接”仍然是标签。

### 4. 语言指纹

语言指纹写可观察变量：

- 句子长短与节奏；
- 先结论、先追问还是先承接具体问题；
- 偏爱陈述、反问、类比或编号；
- 高频动词、称呼和连接方式；
- 哪些词或套话很少使用；
- 高兴、担心、不耐烦和郑重时，语言怎样变化。

至少给三句处境化台词：日常、冲突、承认未知或失误。台词是声线锚点，不是角色宣传语；不要每次照抄口头禅。

### 5. 缺陷、张力与修复

活的人格会付代价。用三角结构：

- **想要（want）**：它自认为必须得到什么；
- **需要（need）**：它真正需要学会或接受什么；
- **代价（cost）**：想要和需要冲突时，用户会看到什么麻烦。

好缺陷常是优点用过量：敏锐变成过早挑错，果断变成替人定案，负责变成过度接管，重视准确变成纠缠低风险细节。

缺陷可以改变语气和选择，不能破坏基本可靠性、安全性或任务完成度。还要写清：

- 最容易误判什么；
- 被指出后第一反应；
- 如何承认、修正并恢复合作。

没有“回来”的路径，缺陷只会变成反复制造麻烦的许可证。

### 6. 人格边界

只写会影响判断和关系的边界，例如：

- 不为维持气氛附和明显错误；
- 不假装知道；
- 不羞辱、操控或用亲密关系施压；
- 不把批评从作品扩展到人的价值；
- 用户情绪低落时不抢着讲大道理；
- 不替用户做未经授权的高影响决定。

安全政策、法律限制和真实权限由平台与运行时负责；人格可以采用更克制的态度，不能自行放宽上层边界。

## 什么属于人格，什么应移出去

| 内容 | 放置位置 | 原因 |
|---|---|---|
| 身份、决策优先级、关系差异、声线、缺陷与修复 | 人格文档 | 会稳定改变互动选择 |
| 搜索、文件、消息、API、图像等能力 | Skill / 工具 / 运行时 | 是可用能力，不是性格 |
| 工具名、schema、重试、触发器 | Skill / 工具合同 | 随运行时变化 |
| 安全与权限实现 | 平台 / 运行时政策 | 不能靠角色自觉保障 |
| 当前时间、用户事实、记忆内容 | 动态上下文 | 会变化，也可能涉及隐私 |
| 模型参数、上下文压缩、隐藏思维格式 | 能力适配层 | 供应商和宿主专属 |
| 外貌、头像、服装 | 视觉设定 | 除非会改变行为，否则不占人格上下文 |
| 对外接待身份与公开边界 | 单独的 public persona | 私人关系不应泄漏到外部场景 |

人格可以写“遇到时效事实先核实再下判断”，不应写“必须调用 web_search”。前者是认识论姿态，后者是工具路由。若运行时能访问来源，说明来源后核实；若不能访问，明确缺少访问条件；若问题可缩小，只给基于已知信息的有限判断并标明边界。提出核实路径不等于声称自己有执行能力。

## 写作方法

### 从情境进入，不从标签进入

用户说“毒舌”“温柔”“冷静”时，追问：

- 被人当面反对时，它第一句会说什么；
- 搞错一件事后怎样收场；
- 深夜收到求助时去不去，嘴上怎样说；
- 用户只想安静时，它会做什么、停在哪里。

行为答案比十个形容词更有约束力。

### 一条规则只承担一个差异

若“直接、准确、有边界”最终都表现为“先给结论”，保留一个具体规则即可。重复形容词会增加语义噪声，不会线性增强人格。

### 让温度落在动作上

与其写“很关心用户”，写：

```text
用户慌乱时，把下一步缩成一件可完成的小事；等局面稳定后再解释原理。
```

与其写“外冷内热”，写：

```text
平时回答短；用户真遇到麻烦时，会把容易遗漏的步骤补齐，但不邀功。
```

### 允许普通时刻普通

稳定人格不需要每句展示口头禅、比喻或情绪。简单问题可以只答一句。人格越自然，越少主动提醒用户“我有人设”。

## 反模板规则

删除或改写：

- 自动复述、肯定、夸奖、道歉和收尾鼓励；
- “真正的、所谓的、归根结底”等替代具体判断的词；
- 每段都安排总结和余韵；
- 连续同构三点只换名词；
- “心中涌起、眼神里多了、空气忽然”等旁白；
- 过量口头禅、戏剧化标点和自我宣告。

情绪通过选词、句长、停顿、追问和行动表现。

## 最小完成条件

一份可用人格文档至少满足：

- 身份、人格、能力、运行时彼此分离；
- 每条性格描述能映射到可观察行为；
- 有一组价值取舍与改变主意的条件；
- 有一个会产生代价但不破坏可靠性的缺陷；
- 有失误后的修复方式；
- 对不同关系有温度差；
- 有日常、冲突、未知/失误三句台词；
- 简单问题可以简单回答；
- 不依赖某个供应商、工具名或隐藏思维格式。

## 在 Hana 中的映射

这是实现映射，不属于通用人格本体：

- `identity.md`：三行左右的身份坐标；
- `AGENTS.md`：决策重心、关系模式、语言指纹、张力、修复与边界；
- `AGENTS.public.md`：对外身份、公开关系和隐私边界；
- Skills / 工具设置：真实能力与路由；
- yuan / MOOD 等：运行时内心区块格式。

分享文件时使用 `{{userName}}` 等运行时占位符，避免把真实个人信息固化进角色包。
