# 跨模型能力适配

## 基本规则

先写模型中立意图，再确认目标模型与运行时能否原生实现。供应商字段只写在适配层，并附降级方案。

不要根据模型名称猜能力。读取当前文档、工具 schema 或运行时状态；无法确认时写成待验证项。

## 能力协商清单

| 设计意图 | 优先确认的原生能力 | 无原生能力时的降级 | 验证重点 |
|---|---|---|---|
| 保持关键指令可见 | 长上下文位置敏感、指令遵循与优先级行为 | 单一权威表述；仅在实测漏遵循时于长材料末尾加同义短提醒 | 冲突、遗漏、位置变化后的遵循率 |
| 调整推理投入 | reasoning/quality/compute 档位或质量模式 | 明确成功标准、依赖、验证循环；换更强模型 | 任务成功、完整性、延迟、token、成本 |
| 控制细节量 | verbosity 或 response-length 参数 | 写“必须保留、可以压缩、优先删除” | 必需信息是否被裁掉 |
| 稳定字段 | JSON Schema、typed output、function/tool schema | 明确字段模板，并在生成后解析校验 | 字段完整、类型、额外文本 |
| 调用工具 | 原生函数调用、并行调用、代码化编排 | 直接逐步调用，外部代码负责编排 | 调用正确率、审批、引用与最终回答 |
| 分解并行工作 | 原生多 Agent、workflow 或宿主并行 | 独立任务顺序执行，保留综合步骤 | 子任务独立性、重复工作、综合质量 |
| 保留跨轮信息 | 会话状态、持久上下文、response id | 重放必要消息，或压缩为目标/决定/证据/未决项 | 过期假设、上下文漂移、token 成本 |
| 缓存稳定前缀 | prompt caching、cache breakpoint | 应用层缓存；保持稳定前缀，动态内容后置 | 命中率、写入成本、失效策略 |
| 精细视觉输入 | image detail、原图尺寸或区域裁剪 | 分块、裁剪、OCR 与坐标复核 | 空间精度、输入成本、遗漏 |
| 隐私与安全标识 | 供应商安全标识、ZDR、存储选项 | 宿主侧匿名标识和最小数据策略 | 数据去向、保留期、可识别性 |

## 适配顺序

1. **锁定可移植核心**：目标、输入、成功标准、权限、证据、输出和停止规则不随供应商字段变化。
2. **列出能力需求**：只写这项任务真正需要的能力，不列产品功能大全；同时记录目标模型的指令遵循、长上下文位置敏感、默认详略、工具行动和结构化输出表现。
3. **确认支持情况**：查当前模型、API 与宿主文档；记录版本和日期。
4. **选择最小适配**：优先一个能解决实测缺口的旋钮。
5. **定义降级**：字段不可用、工具失败或模型较弱时怎样保持可接受行为。
6. **同题比较**：在代表性任务上测任务成功、完整性、证据质量、延迟、token 用量和成本；运行时没有某项遥测时明确标为“不可观测”。

跨模型迁移的交付物必须附这份同题验收矩阵。只列参数待确认项而不说明如何比较迁移结果，适配层仍未闭环。

## 条件性策略

### 推理与质量模式

更高推理投入只在任务足够困难且评测显示收益时使用。常见误区是用更高预算掩盖：

- 完成标准缺失；
- 依赖关系没写；
- 工具路由含糊；
- 验证循环不存在；
- 输入证据不完整。

要求模型给出可检查的结论、证据、假设、计算和验证结果。不要要求披露隐藏思维链。

### 结构化输出

原生 schema 可降低格式漂移，但仍需验证语义完整性。程序或工具输出正确，不代表最终自然语言回答保留了必需字段、引用或限制；两层都要测。

### 工具编排

代码化或批量编排适合确定性归并阶段：过滤、连接、排序、去重、聚合、批量校验。以下情况保留直接模型判断：

- 每个结果会改变下一步；
- 需要人类审批；
- 中间材料很小；
- 必须保留原生引用或附件；
- 需要逐步语义判断。

### 会话状态与缓存

跨轮状态只在目标、假设和优先级仍稳定时复用。状态陈旧会锚定旧方案。压缩应发生在里程碑，保留目标、已做决定、证据、约束和未决项。

缓存是成本与延迟优化，不能改变语义。保持大块稳定前缀，动态任务数据后置；只有测得收益时才引入显式断点。

## OpenAI GPT-5.6 示例映射，非可移植核心

来源：[GPT-5.6 model guidance](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6) 与 [Prompting guidance for GPT-5.6 Sol](https://developers.openai.com/api/docs/guides/prompt-guidance-gpt-5p6.md)，检索于 2026-08-21。

以下字段只能在对应 API 和模型确认支持后使用：

- 推理投入：`reasoning.effort`，文档列出 `none`、`low`、`medium`、`high`、`xhigh`、`max`；
- 质量优先模式：`reasoning.mode: "pro"`；
- 细节量：`text.verbosity` 的 `low`、`medium`、`high`；
- 持久推理上下文：`reasoning.context`；
- 代码化工具编排：`programmatic_tool_calling` 与 `allowed_callers`；
- 显式缓存：`prompt_cache_options`；
- 图像精度：`original` 或 `auto` detail。

这些名称、取值、默认值、价格和行为会随版本变化。迁移到其他供应商时只迁移设计意图，不照搬字段。
