# Universal Model Prompting

把提示词当作一份可测试的行为合同：说明要抵达的结果、完成标准、可用证据、行动边界和停止条件，让模型在边界内选择路径。

## “通用”的含义

通用指**核心意图可跨模型迁移**，不表示同一段文字在所有模型上都达到相同最优结果。

始终分开两层：

1. **可移植核心**：目标、上下文、成功标准、约束、权限、工具语义、输出与验证。
2. **能力适配层**：某个供应商或模型支持的推理档位、原生结构化输出、持久状态、缓存、批量工具编排等旋钮。

不要把供应商字段写进可移植核心。目标模型未知时，只交付核心与待确认的能力清单。

## 触发边界

使用本 Skill：

- 从零设计提示词、系统指令、工具说明或 Agent 规则；
- 精简、审计、迁移、合并或调试现有 prompt stack；
- 定义自治、审批、检索、引用、工具路由、输出格式或停止规则；
- 把人格设定变成模型可执行的行为规则；
- 比较同一提示在不同模型上的适配方式。

不要因为本 Skill 默认启用，就在普通问答、写作、分析或执行任务前重写一遍提示词。只有“模型该如何被指示”本身属于任务时才使用。

用户要完整创建角色卡或“捏人”时，按用户指定的工具或流程走；本 Skill 只在编写、迁移或审计人格提示本身时提供模型中立方法。

## 先确定逻辑分层

提示栈宜按职责分层；具体消息角色服从运行时实现：

| 层 | 放什么 | 不放什么 |
|---|---|---|
| 平台与运行时 | 安全政策、权限、真实工具能力、消息优先级 | 虚构能力、人格修辞 |
| 可移植全局核心 | 稳定的协作方式、证据原则、自治边界、质量标准 | 单次任务数据、供应商参数 |
| 人格 | 决策倾向、关系模式、语言指纹、缺陷与修复方式 | 工具清单、触发器、权限实现 |
| 任务合同 | 本次目标、输入、完成标准、限制、输出、停止条件 | 与任务无关的长期设定 |
| 能力适配 | 已确认支持的模型/API 旋钮与降级方案 | 被包装成普遍规律的专属字段 |

能力适配层内部再分为“按能力画像选用的条件策略”和“仅命中对应平台时注入的供应商字段附录”。

高优先级政策和用户当前意图始终优先。人格只改变取舍与表达，不削弱事实准确性、安全性或任务完成度。

## 工作流

### 1. 建立基线

先收集能改变设计的信息：

- 现有提示、真实失败样例或对话轨迹；
- 用户可见结果和使用场景；
- 目标模型、供应商与运行时；若已知，再确认指令遵循、长上下文位置敏感、默认详略、工具行动和结构化能力，不凭名称猜；
- 可用工具、数据来源、可逆性与外部副作用；
- 当前可衡量的质量、延迟和成本基线。

已有可用提示时，先保留行为基线，再做小步修改。不要同时更换模型、提示、工具集和推理档位后猜测原因。

只追问会实质改变目标、权限或交付格式的缺口。其余缺口写明合理假设后继续。

### 2. 写出任务合同

复杂提示至少回答：

- **角色与上下文**：模型在什么业务或协作位置工作；
- **目标**：用户最终能看到或使用什么；
- **输入与证据**：哪些材料可信，缺失时如何处理；
- **成功标准**：结束前必须为真的可检查条件；
- **约束**：政策、范围、事实、格式、成本、时间与副作用边界；
- **工具**：何时调用、关键返回、错误与回退；
- **输出**：必含内容、结构、长度优先级；
- **停止规则**：何时继续、重试、追问、降级、拒答或结束。

优先描述目的地。只有流程顺序影响正确性、安全、证据链或审批时，才规定步骤。

### 3. 把判断题写成决策规则

绝对词只留给真正不变量，例如安全红线、必需字段和禁止副作用。面对搜索、追问、工具选择、迭代深度等判断题，写“条件 → 动作 → 停止条件”。

例如：

```text
若缺少的字段会改变资格判断，询问最小缺失字段；
若只影响次要措辞，标注假设并继续。
```

避免宽泛关键词映射、万能默认值和无法覆盖边界情况的“永远”。

### 4. 精简并消除冲突

从能工作的版本开始逐组删减，再跑同一批测试：

- 默认每条规则只保留一处权威表述；若目标模型指令遵循较弱，或长上下文测试显示漏掉关键不变量，可在材料首尾或使用点有意重复同义短提醒，并标注原因。不要用重复而宽泛的“先问我”替代一份清楚的权限边界；
- 删除未经测试的重复风格词、流程旁白和无关工具；
- 保留产品要求、关键边界，以及修复已测缺陷的示例；
- 逐项检查互斥目标、权限冲突和格式冲突；
- 长对话在里程碑压缩状态，保留目标、决定、证据与未决项。

短本身不是目标。删减后仍须覆盖正确性、证据、权限、输出和验证。

### 5. 定义自治与审批边界

按动作影响划分，而非重复“先问我”：

- 回答、解释、审阅、诊断、规划：可读取相关材料并报告；除非用户也要求改变，不自行实施。
- 改动、构建、修复：可完成用户明确授权范围内的本地、可逆修改，并运行非破坏性验证。
- 外部写入、破坏性动作、购买或显著成本、隐私披露、权限扩大、实质扩展范围：先确认。

真实运行时政策若更严格，以运行时为准。长任务标明当前处于研究、设计、实施、审查还是外部协调，防止静默跨层。

### 6. 让工具路由服从任务形状

只暴露相关工具。工具说明应覆盖用途、触发条件、关键输入输出、错误语义与副作用。

- 前置检索或验证决定正确性时，明确禁止跳过；
- 独立读取可并行，后一步依赖前一步时保持串行；
- 并行检索后先综合，再采取写入动作；
- 空结果、部分结果或异常狭窄结果出现时，尝试一两个有意义的替代路径；
- 批量程序编排只用于边界清楚、可确定性归并的阶段；语义判断、引用保真、审批和最终验证保留给直接模型判断；
- 给出重试上限、停止条件和结构化失败输出，避免死循环与重复调用。

### 7. 规定证据与不确定性

说明哪些主张必须有证据、怎样算足够、来源冲突如何呈现，以及证据缺失时如何缩小结论。

- 只引用实际读取的来源；
- 引用紧邻其支撑的主张；
- 分开事实、来源自述、推断和创作；
- 没搜到不自动等于事实上的“没有”；
- 缺关键证据时询问最小字段、换最小回退或明确保留未知；
- 检索预算服务于承重事实，不为润色和无关例子追加搜索。

### 8. 定义长度、风格与人格

长度用内容优先级约束，而非只写“简短”：

```text
保留结论、必要证据、关键限制、决定与下一步；
先删开场、重复、通用安慰和可选背景。
```

风格写成可观察选择：先结论还是先承接问题，何时安慰，句长怎样变化，何时省略签名。少用“友好、专业、有同理心”等孤立标签。

涉及长期人格时，读取：

- `references/persona/persona-definition.md`
- `references/persona/persona-template.md`
- `references/persona/persona-tests.md`

人格与协作风格保持短而具体，不能替代任务目标、工具规则和成功标准。

### 9. 建立能力适配层

读取 `references/model-adaptation.md`。先确认能力，再映射：

- 推理预算或质量模式；
- 原生 verbosity；
- JSON Schema 或其他结构化输出；
- 直接、批量、代码化或多 Agent 工具编排；
- 会话状态、缓存与多模态精度；
- 不支持时的文本降级与验证方案。

不要要求模型披露隐藏思维链。需要可靠性时，索取可检查的结论、证据、计算、假设与验证结果。

跨模型或跨供应商迁移时，适配层必须附一份同题验收方案，至少比较任务成功、输出完整性、证据质量、延迟、token 用量和成本。运行时不能提供某项遥测时标为“不可观测”，不要静默省略。

### 10. 验证后再定稿

用真实、代表性输入检查：

- 正常路径、缺信息、冲突指令、工具失败和边界动作；
- 输出是否完整，证据是否贴合，副作用是否越界；
- 中间结构正确时，最终回答是否仍保留必需字段；
- 人格在冲突、未知、失误、情绪和日常场景是否稳定；
- 不同目标模型上是否需要适配，而非假定表现一致。

修改时一次只改一个有依据的变量。优先补缺失合同、依赖、路由或验证，再提高推理预算。

## 交付格式

用户未指定格式时，按需交付：

1. **诊断**：现有提示的主要失败机制与保留项；
2. **可移植核心提示**：可直接复制；
3. **能力适配说明**：仅列已确认的模型/运行时差异；
4. **代表性测试**：3 至 7 个真实场景与检查点；跨模型迁移必须包含同题对照矩阵，覆盖成功、完整性、证据、延迟、token 与成本；
5. **迁移说明**：改了什么、为什么、如何回滚。

用户只要最终提示时，把可复制提示放在最前，说明压缩到必要程度。

## 完成检查

- [ ] 用户可见结果与完成标准明确；
- [ ] 每条指令有单一权威表述且没有冲突；任何有意重复都有模型/长上下文测试依据，措辞保持一致；
- [ ] 判断题使用条件规则，不滥用绝对词；
- [ ] 本地行动、外部副作用和扩展范围的权限清楚；
- [ ] 工具说明包含路由、返回、失败和停止；
- [ ] 关键事实有证据规则，未知不会被流畅地填空；
- [ ] 输出长度规定“保留什么、先删什么”；
- [ ] 人格、任务能力、运行时政策和供应商参数彼此分离；
- [ ] 供应商专属字段只存在于适配层；
- [ ] 跨模型迁移附有同题对照指标；不可取得的遥测已明确标记，而非省略；
- [ ] 测试覆盖真实输入与失败路径，修改可归因、可回滚。
